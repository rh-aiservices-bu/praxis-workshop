= Praxis on OpenShift AI: Showroom lab guide

A hands-on workshop for link:https://github.com/praxis-proxy/praxis[Praxis^], the Rust proxy framework, and link:https://github.com/praxis-proxy/ai[Praxis AI^], the AI gateway built on it. It runs on Red Hat OpenShift AI, with published images and simulated models served as KServe InferenceServices: no local build and no GPUs.

This repository contains:

* The **Showroom site** at the root: Red Hat Showroom content built with link:https://antora.org[Antora^] and the RHDP Showroom theme (`rh-one-2025`)
* The **lab source** in `lab/`: tested OpenShift manifests and scripts, background docs, and an optional local podman version

== Layout

[source,text]
----
site.yml                         Antora playbook (title, theme)
ui-config.yml                    Showroom right panel: Terminal + OCP Console
content/antora.yml               Component and environment attributes
content/modules/ROOT/
  nav.adoc                       Navigation
  partials/_attributes.adoc      Shared attributes and tested versions
  pages/                         index, overview, details, 3 modules, conclusion
  examples/                      Manifests, included inline by the pages
lab/
  README.md                      Lab overview
  CONCEPTS.md, AI.md             Background: how Praxis and Praxis AI work
  openshift/                     The lab: manifests, setup.sh, teardown.sh, walkthrough
    prereqs/                     Installs OpenShift AI with KServe, if the cluster lacks it
  local/                         Optional: podman version for a laptop
----

The manifests in `content/modules/ROOT/examples/` are copies of the tested files in `lab/openshift/`. Pages include them with `include::example$<file>[]` inside `oc apply` commands, so learners don't need a copy of this repository. Keep the two copies in sync.

Some manifests are split into one file per step, so each block learners run stays short:

* `05-echo-service.yaml` and `05-echo-deployment.yaml` are one-server templates applied in a loop. Together they must produce the objects in `lab/openshift/05-echo.yaml`.
* `10-serving-runtime.yaml` matches `lab/openshift/10-serving-runtime.yaml`, and the three `11-*.yaml` files (one InferenceService each) together must match `lab/openshift/11-models.yaml`.
* The five `06-basics-*.yaml` files together must match `lab/openshift/06-praxis-basics.yaml`.
* The five `20-ai-*.yaml` files (excluding `-with-llama`) together must match `lab/openshift/20-praxis-ai.yaml`.
* `20-ai-configmap-with-llama.yaml` is the ConfigMap from `lab/openshift/solutions/20-praxis-ai-with-llama.yaml`; the Module 3 exercise solution applies only the ConfigMap.

== Running the lab without Showroom

The cluster needs Red Hat OpenShift AI 3.x with KServe enabled. If it doesn't have it, install it first with the files in `lab/openshift/prereqs/` (see `lab/openshift/README.md`). Then:

[source,sh]
----
lab/openshift/setup.sh
----

Then follow `lab/openshift/README.md`. Everything goes into the `praxis` namespace; `lab/openshift/teardown.sh` removes it.

== Publishing

The workflow in `.github/workflows/gh-pages.yml` builds the site with Antora 3.1.10 on Node 22:

* **Pushes to `main`** build the site and publish it to GitHub Pages.
* **Pull requests** only build it, and fail on any Antora warning (for example a broken include), so problems are caught before merging.
* **Changes only under `lab/`** don't trigger a build, because they don't affect the site.
* **Manual runs** are available from the **Actions** tab (`workflow_dispatch`).

One-time setup: in the repository's **Settings** → **Pages**, set **Source** to **GitHub Actions**. The site is then served at `https://<owner>.github.io/<repo>/`.

For an RHDP catalog item, point the Showroom workload at this repository and `site.yml`.

== Previewing locally

From the root of this repository (it must be a git repository with at least one commit, because Antora reads content from git):

[source,sh]
----
podman run --rm --name antora -v $PWD:/antora:z -p 8080:8080 -i -t ghcr.io/juliaaano/antora-viewer
----

Then open http://localhost:8080. Rerun the container after editing content; live reload isn't supported.

To build the static site only:

[source,sh]
----
npx antora@3.1 generate site.yml
----

The output goes to `www/`.
