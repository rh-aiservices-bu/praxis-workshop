== What you've learned

Throughout this workshop, you've gained hands-on experience with:

* ✅ How Praxis builds a pipeline per listener from named filter chains, and how a request flows through it
* ✅ Path and header routing, round-robin and weighted load balancing, rate limiting and active health checks
* ✅ Hot reload from a ConfigMap, including how invalid changes are rejected
* ✅ Routing AI traffic by the `model` in the request body, with Praxis balancing model pods itself
* ✅ Serving Anthropic Messages clients from OpenAI Chat Completions backends, streaming included
* ✅ Per-model token and time-to-first-token metrics in OpenShift monitoring

You now have the skills to run Praxis as a general-purpose gateway and as an AI gateway on OpenShift.

== Key takeaways

. **Everything is a filter**: routing, load balancing, rate limiting and AI parsing all use the same filter model, arranged into chains and pipelines.
. **Routing and load balancing are separate decisions**: the router picks a cluster, the load balancer picks an endpoint, and AI routing reuses both.
. **Classify, promote, route**: turn something in the request, such as the `model` field, into a header, then route on the header.
. **Safe by default**: private backends need an allowlist, reserved headers can't be spoofed, and invalid configuration never replaces a working one.
. **Praxis AI is Praxis core plus AI filters**: one configuration model from proxy basics to the AI gateway.

== Things to know before using Praxis for real

These came up while building this workshop:

* **Connection settings belong on the `load_balancer` cluster entries.** Proxied traffic uses the cluster as the `load_balancer` declares it. `trusted_private_endpoints` set only on a top-level cluster lets the health checker probe, but doesn't apply to requests.
* **Praxis {praxis_version} needs endpoints repeated.** Each `load_balancer` cluster entry must list its own endpoints, even when a top-level cluster of the same name has them. Newer Praxis copies them automatically. Praxis AI {praxis_ai_version} is built on core {praxis_version}, so this applies to it too.
* **Replies Praxis generates itself skip response-phase headers.** Static responses, 404s and 429s don't get headers that response filters add.
* **Experimental filters aren't in the published images.** `token_ceiling`, `token_rate_limit` and the OpenAI Responses filters need a custom build or an `-experimental` image.
* **`token_usage_headers` can't work with OpenAI or Anthropic backends.** Their usage arrives in the response body, after the headers are sent. Use the token metrics.
* **The metrics listener must bind `0.0.0.0`** so kubelet probes and Prometheus can reach it. In production, restrict it with a NetworkPolicy.
* **OpenShift's defaults just work.** The images run unmodified under `restricted-v2`. The only change needed was running whoami on port 8080.
